# Ретранслятор отчётов

Программа на машинах открытая, поэтому ключ от GitHub в ней хранить нельзя. Отчёты об
обновлениях (только с машин, где пользователь разрешил их отправку) идут сюда — на маленький
Worker в Cloudflare (в программе и в её README он называется «сервер для отчётов»). Он проверяет
каждый отчёт и записывает его в закрытый репозиторий `Purple-Palm/arch-update-cactus-reports`:

- лог обновления — файлом `logs/ГГГГ/ММ/<ID>-<дата-время>.log` в ветке `logs-<ID>`: у каждой
  машины своя ветка (ID — 8 символов, он виден в Настройках на машине и есть в каждом отчёте),
  поэтому все логи одной машины удаляются одним нажатием;
- issue с итогом: модель машины, что обновилось, проблемы и предупреждения, конец лога.
  Issue чистого обновления сразу закрывается, поэтому **открытые issues — это те, что стоит посмотреть**.
  Метки: `ок`, `предупреждения`, `проблемы`, `не начато`, `chromebook`.

Всё делается в браузере. Командная строка нужна один раз — для проверки (шаг 5): в PowerShell на Windows или в терминале Linux.
Бесплатно: хватает бесплатных тарифов GitHub и Cloudflare, банковская карта не нужна.

## 1. Закрытый репозиторий для отчётов

1. Открой ссылку — в ней уже заполнены имя и видимость:
   https://github.com/new?name=arch-update-cactus-reports&visibility=private
2. **Repository name**: `arch-update-cactus-reports` (по ссылке уже стоит, проверь).
3. Видимость — **Private** (по ссылке уже выбрана, проверь).
4. Переключатель **Add README** — в положение **On**. Обязательно: ветки для логов ретранслятор
   делает от первого коммита, а в пустом репозитории его нет.
5. **Create repository**.
6. Чтобы отчёты не попадали в почту: на странице нового репозитория справа вверху **Unwatch**
   (или **Watch**) → **Participating and @mentions** (или **Custom** без галочки у **Issues**).
   За репозиториями, которые ты создаёшь, GitHub следит сам.
7. И проверь, что GitHub не пишет тебе о твоих же действиях: аватар → **Settings** →
   **Notifications** → **Customize email updates** — галочки **Include your own updates** быть
   не должно (по умолчанию её нет). Issues ретранслятор заводит и закрывает твоим токеном, то есть
   от твоего имени, и с этой галочкой о каждом пришло бы письмо.

   Если письма об issues отчётов всё же приходили, это копии отчётов (в них модель машины, итог и
   конец лога): удаляя отчёты машины, удали и их (раздел «Удалить отчёты одной машины»).

## 2. Токен GitHub только для этого репозитория

1. Открой ссылку — в ней уже заполнены название, срок и права:
   https://github.com/settings/personal-access-tokens/new?name=arch-update-reports&description=Relay+for+Arch+Update+by+Cactus+reports&expires_in=366&contents=write&issues=write
2. **Resource owner**: `Purple-Palm`.
3. **Repository access**: **Only select repositories** → выбери `arch-update-cactus-reports`.
   Только его — не «All repositories».
4. **Permissions** → вкладка **Repositories** (на старой странице — раздел **Repository permissions**);
   по ссылке права уже стоят, проверь:
   - **Contents**: **Read and write** — записывать логи и делать для них ветки;
   - **Issues**: **Read and write** — заводить и закрывать issues, создавать метки;
   - **Metadata**: **Read-only** — GitHub добавляет сам, без неё нельзя.

   Больше ничего не добавляй.
5. **Expiration**: 366 дней (столько стоит по ссылке, это самый долгий срок с датой).
   Можно выбрать и **No expiration**, но безопаснее со сроком: что делать, когда он кончится, — в разделе «Замена токена».
6. **Generate token** и сразу скопируй токен (`github_pat_…`): GitHub показывает его один раз.
   Никуда, кроме шага 4, его не вставляй и никому не отправляй.

## 3. Аккаунт Cloudflare

1. https://dash.cloudflare.com/sign-up — почта и пароль, потом подтверди почту по письму.
2. Тариф не выбирай — Workers бесплатны (100 000 запросов в день; отчётов будет несколько в день).

## 4. Worker

1. В панели Cloudflare слева: **Workers & Pages** (может быть внутри раздела **Compute**).
2. **Create** (или **Create application**) → **Start with Hello World!**
   (или шаблон **Hello World** / **Create Worker**; если предлагают подключить Git — не нужно).
3. Имя: `arch-update-reports` → **Deploy**. Если Cloudflare попросит выбрать поддомен
   `workers.dev` для аккаунта — придумай нейтральный, без имени и почты (он будет виден в открытой
   программе), например `purple-palm`.
4. На странице Worker'а — **Edit code**. Слева открыт файл `worker.js`:
   выдели в нём всё (Ctrl+A) и удали.
5. Открой код ретранслятора (версия, прошедшая тесты): https://raw.githubusercontent.com/Purple-Palm/arch-update-cactus/stable/relay/worker.js —
   Ctrl+A, Ctrl+C, вернись в редактор, Ctrl+V. Справа вверху — **Deploy**.
6. Вернись на страницу Worker'а → **Settings** → **Variables and Secrets** → **Add**
   (если над разделом есть выбор **Production** / **Previews Base** — должно быть **Production**):
   - **Type**: **Text**, **Variable name**: `REPO`, **Value**: `Purple-Palm/arch-update-cactus-reports`;
   - **Add variable** → **Type**: **Secret**, **Variable name**: `GITHUB_TOKEN`, **Value**: токен из шага 2.

   Нажми **Deploy**. Секрет Cloudflare хранит зашифрованным и больше никому не показывает — даже тебе.
7. Адрес Worker'а — на его странице (раздел **Domains & Routes** или ссылка **Visit**), вида
   `https://arch-update-reports.ПОДДОМЕН.workers.dev`; скопируй его, он понадобится в шагах 5 и 6.
   Если открыть его в браузере, Worker ответит
   `{"ok":false,"error":"сюда отчёты отправляют методом POST"}` — так и должно быть.

   Этот адрес будет записан в открытой программе — прочитать его сможет любой. Посмотри, что в нём
   на месте `ПОДДОМЕН`: Cloudflare выбирает поддомен аккаунта сам, и в нём может оказаться имя или
   часть почты. Если так — смени его: слева **Workers & Pages** → справа **Your subdomain** →
   **Change** → что-нибудь нейтральное, например `purple-palm`. Адрес Worker'а сменится вместе с ним
   (новому иногда нужно несколько минут, чтобы заработать) — потом скопируй его заново.
8. **Обязательно: выключи журнал запросов.** Cloudflare сам включает его каждому новому Worker'у
   и 3 дня хранит в нём каждый запрос — вместе с IP-адресом отправителя и тем, где он примерно
   находится (страна, город). А пользователям обещано, что их адреса не хранятся. Поэтому:
   страница Worker'а → **Settings** → раздел **Observability** (опять **Production**, если есть
   выбор) → у **Workers Logs** выключи переключатель (если вместо него кнопка **Edit** — нажми её
   и выключи там) → сохрани (**Save** или **Deploy** — какая кнопка будет). **Traces** и **Issues**
   там же оставь выключенными, как они стоят сразу. Проверишь, что журнал не пишется, в шаге 5.

## 5. Проверка (PowerShell или терминал Linux)

Скопируй пример ниже в Блокнот и замени в первой строке весь адрес
`https://arch-update-reports.ПОДДОМЕН.workers.dev` на тот, что скопировал в шаге 4.7 (`/report`
в конце оставь). Потом открой PowerShell (Пуск → «PowerShell») и вставь туда всё из Блокнота:

```powershell
$url = "https://arch-update-reports.ПОДДОМЕН.workers.dev/report"
$report = @{
    schema  = 1
    id      = "00000000"
    time    = (Get-Date).ToUniversalTime().ToString("s") + "Z"
    updater = @{ commit = "test"; date = "" }
    device  = @{ vendor = "Test"; model = "PowerShell"; chromebook = $false; cpu = "Test CPU"; cores = 4; ram_gib = 8 }
    update  = @{ mode = "auto"; verdict = 1; started = $true; seconds = 42
                 changed = @("gnupg"); added = @(); removed = @()
                 problems = @(); warnings = @("test warning"); ok = @("test ok") }
    log     = "test line 1`ntest line 2`n"
}
$json = $report | ConvertTo-Json -Depth 5
try {
    Invoke-RestMethod -Method Post -Uri $url -ContentType "application/json; charset=utf-8" `
        -Body ([Text.Encoding]::UTF8.GetBytes($json))
} catch {
    $_.Exception.Message
    $_.ErrorDetails.Message
}
```

То же из терминала Linux (адрес замени так же):

```bash
curl -sS -X POST https://arch-update-reports.ПОДДОМЕН.workers.dev/report -H 'Content-Type: application/json' --data @- <<EOF
{"schema": 1, "id": "00000000", "time": "$(date -u +%Y-%m-%dT%H:%M:%SZ)",
 "updater": {"commit": "test", "date": ""},
 "device": {"vendor": "Test", "model": "PowerShell", "chromebook": false, "cpu": "Test CPU", "cores": 4, "ram_gib": 8},
 "update": {"mode": "auto", "verdict": 1, "started": true, "seconds": 42, "changed": ["gnupg"], "added": [],
            "removed": [], "problems": [], "warnings": ["test warning"], "ok": ["test ok"]},
 "log": "test line 1\ntest line 2\n"}
EOF
```

Ответ должен быть `{"ok":true,"issue":…}`.

В PowerShell должна напечататься табличка: `True` под `ok` и номер issue под `issue`. В репозитории отчётов
появятся issue «⚠ … · Test PowerShell · 1 пакет · 00000000» с меткой `предупреждения` и ветка
`logs-00000000` с файлом лога (переключатель веток над списком файлов). Тестовое можно удалить:
issue — на его странице справа внизу **Delete issue**, ветку — как в разделе «Удалить отчёты одной машины».

Теперь проверь журнал (шаг 4.8): страница Worker'а → вкладка **Observability** (или **Logs**).
Только что сделанного запроса там быть не должно: пусто, или Cloudflare предлагает журнал включить,
или видны только записи, сделанные до шага 4.8. Если запрос там есть — журнал не выключился:
повтори шаг 4.8 и проверь ещё раз. Смотреть запросы вживую, ничего не сохраняя, можно и с
выключенным журналом: там же **Live** (Real-time logs) — пригодится, если что-то не работает.

Если вместо таблички ошибка:

| что напечаталось | что значит | что сделать |
|---|---|---|
| `Hello World!` | в Worker'е всё ещё код-пример | шаги 4.4–4.5: вставь код целиком и нажми **Deploy** |
| 400 | отчёт не прошёл проверку (в ответе написано, какое поле) | вставь пример ещё раз целиком |
| 404 | не тот адрес | в конце адреса должно быть `/report` |
| 1042, «не удаётся разрешить имя», ошибка SSL/TLS | адрес не тот | скопируй адрес из шага 4.7 целиком; если только что сменил поддомен — подожди несколько минут |
| 429 | слишком много отчётов за час | подожди час (счётчики в памяти Worker'а обнуляет и новый **Deploy**) |
| 500 | сбой ретранслятора | попробуй ещё раз через несколько минут; если повторяется — напиши разработчику |
| 502 «репозиторий отчётов пустой» | в репозитории нет ни одного коммита | шаг 1.4: на странице репозитория добавь README, потом повтори |
| 502 | GitHub не принял запись | проверь токен: репозиторий `arch-update-cactus-reports`, права Contents и Issues — Read and write, срок не истёк |
| 503 | не заданы `REPO` или `GITHUB_TOKEN` (или GitHub попросил подождать — это написано в ответе) | шаг 4.6, и не забудь **Deploy**; если «подождать» — повтори через несколько минут |
| 1101 | Worker упал с ошибкой | проверь, что код вставлен целиком (шаги 4.4–4.5); если не помогло — напиши разработчику |
| 1102 | Worker превысил лимит Cloudflare на время процессора | попробуй ещё раз; если повторяется — напиши разработчику |

## 6. Адрес — разработчику

Пришли разработчику адрес из шага 4.7 с `/report` в конце — тот же, что проверил в шаге 5:
`https://arch-update-reports.ПОДДОМЕН.workers.dev/report`. Он впишет его в программу
(`ENDPOINT` в `lib/report.py`); после самообновления машины начнут отправлять отчёты — только те,
где пользователь разрешил. Отчёты, накопленные до этого (до 20 на машину), уйдут постепенно.

## Удалить отчёты одной машины

Об этом просят issue в публичном репозитории `arch-update-cactus` с ID машины — 8 символов,
например `3f9a0c21`. Всё делается в репозитории отчётов (и в почте, если туда приходили письма о них):

1. **Логи.** Вкладка **Code** → над списком файлов **Branches** (или сразу
   https://github.com/Purple-Palm/arch-update-cactus-reports/branches/all) → у ветки `logs-3f9a0c21`
   значок корзины (**Delete branch**). Логи этой машины лежат только в её ветке, так что они
   уходят все сразу.
2. **Issues.** Вкладка **Issues** → в строке поиска сотри всё и введи `is:issue 3f9a0c21 in:title`
   (так найдутся и открытые, и закрытые) → открой каждый → справа внизу **Delete issue** →
   подтверди. Удалённый issue не восстанавливается.
3. **Почта.** Если GitHub присылал письма об этих issues (шаги 1.6–1.7), это копии отчётов: найди
   их в почте по ID машины и удали, и из корзины тоже.
4. Ответь в issue публичного репозитория, что всё удалено, и закрой его.

Если машина и дальше присылает отчёты (на ней их не выключили), ветка и issues появятся снова.

Удалённую ветку GitHub какое-то время ещё хранит у себя: её коммиты открываются по прямой ссылке
(только тебе — репозиторий закрытый). Стереть их с серверов GitHub совсем может только поддержка
GitHub по просьбе или удаление всего репозитория отчётов.

## Замена токена

За несколько дней до конца срока GitHub пришлёт письмо. Тогда (или если токен попал не туда):

1. GitHub → аватар → **Settings** → **Developer settings** → **Personal access tokens** →
   **Fine-grained tokens** → `arch-update-reports` → **Regenerate token**: права и репозиторий
   останутся те же, будет новый срок и новый токен. Скопируй его.
   (Если такой кнопки нет — создай новый токен по ссылке из шага 2, а старый удали.)
2. Cloudflare → Worker → **Settings** → **Variables and Secrets** → у `GITHUB_TOKEN` значок
   редактирования → вставь новый токен → **Deploy**.

Пока токена нет или он истёк, ретранслятор отвечает ошибкой, и отчёты ждут на машинах
(до 20 на каждой) — после замены они придут сами.

## Обновить код ретранслятора

Если разработчик попросит: страница Worker'а → **Edit code** → выдели всё и удали → вставь код
по ссылке из шага 4.5 → **Deploy**. `REPO` и `GITHUB_TOKEN` остаются как были. Потом загляни в
**Settings** → **Observability**: **Workers Logs** должен остаться выключенным (шаг 4.8).

## Выключить

- **На время**: удали секрет `GITHUB_TOKEN` (Settings → Variables and Secrets) или отзови токен на GitHub.
  Отчёты будут ждать на машинах и придут, когда вернёшь токен.
- **Совсем**: удали Worker (**Settings** → внизу **Delete**), удали токен на GitHub и скажи
  разработчику, чтобы убрал адрес из программы. Репозиторий отчётов можно удалить
  (его **Settings** → внизу **Delete this repository**).

## Что достаётся Cloudflare

Cloudflare хранит токен и пропускает отчёты через себя. Токен же даёт доступ только к одному
закрытому репозиторию `arch-update-cactus-reports` и только к двум вещам: файлам (Contents) и
issues (Issues), плюс обязательный Metadata (только чтение). Ни к программе `arch-update-cactus`,
ни к другим репозиториям, ни к настройкам аккаунта он не даёт ничего. Так что тот, кто получил бы
токен из Cloudflare, смог бы читать и менять файлы и issues этого одного репозитория — дописать,
переписать или стереть логи и ветки, изменить или закрыть issues, — и ничего за его пределами;
и только пока токен не отозван.

## Защита от мусора

Адрес ретранслятора есть в открытой программе, поэтому прислать что-то может кто угодно.
Ретранслятор принимает только отчёты правильного вида (не больше 1,5 МиБ, лог не больше 1 МиБ);
не больше 6 запросов в час с одного адреса (у IPv6 — с одной сети /64) и 6 отчётов в час от одной
машины — эти счётчики живут в памяти Worker'а; и не больше 20 отчётов в час и 60 в сутки всего —
это он проверяет по самому репозиторию, так что и нарочно присланного мусора наберётся не больше
примерно 60 issues в сутки. Когда предел набран, лишним запросам Worker отказывает сам, не
спрашивая GitHub. IP-адрес отправителя он не хранит и никуда не передаёт: для счётчика берётся
только хэш от него.

Если в репозиторий всё-таки пошёл мусор — выключи ретранслятор на время (раздел «Выключить»)
и напиши разработчику.

**Журнал запросов Worker'а (Workers Logs) должен быть выключен** (шаг 4.8). Cloudflare включает
его сам каждому новому Worker'у и 3 дня хранит в нём IP-адрес и примерное место каждого, кто
прислал отчёт. Если создаёшь Worker заново — выключи и у нового. А если журнал когда-нибудь
понадобится, в README программы надо будет честно написать, что Cloudflare 3 дня хранит адрес
отправителя.
